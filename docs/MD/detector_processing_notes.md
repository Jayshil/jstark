# jstark detector processing: development notes

As of 2026-11-20. The record of what was discussed, decided, implemented
and measured while building the detector-processing stage of jstark
(`jstark/reduction/`), for anyone continuing the work, including future
work sessions. The code and its docstrings remain the reference for
details; `docs/reduction.rst` is the user-facing walk-through.

---

## 1. Goal and working agreements

- **Goal of jstark:** a modular toolkit for JWST time-series observations of
  transiting exoplanets, from raw `uncal` files to transmission, emission and
  phase-curve spectra.
  - **Modular, not one-shot:** every intermediate product can be inspected,
    and every step stopped, changed and resumed.
  - **Built on the official `jwst` pipeline**, with custom steps where
    tests showed the standard ones fall short.
- **Modes supported:**

  | Instrument | Modes |
  | --- | --- |
  | NIRSpec BOTS | PRISM, G395H, G235H, G395M, G235M |
  | NIRISS | SOSS |
  | NIRCam LW grism (GRISMR) | F444W, F322W2 |
  | MIRI | LRS slitless, F1500W imaging |

- **Status:** the detector-processing stage (uncal → cleaned cubes) is
  finished for now. **Next: spectral extraction.**
- **Agreements with the user:**
  - Give a plan before executing large pieces of work.
  - The code must always use **all segments** of an exposure unless told
    otherwise, but **tests use only one segment**.
  - Segments are **never stitched** into one cube, since exposures with
    20+ segments would be too large. Everything works segment by segment.
  - Defaults follow published practice, but each default must be justified by
    a test on real data where possible, and is changed when the data say so
    (e.g. the MIRI ramp start, §6.9).
  - Bad pixels are kept as a **2D persistent map** plus a **3D transient
    mask**.
  - `jwst>=2.0` is required; the environment runs jwst 3.0.0.
  - G235H and G235M are not to be tested for now (no data).

## 5. Stage by stage

### 5.1 Stage 1 (uncal → rateints)

- **Mode detection and recipe:** the mode is read from the header. Each mode
  has an ordered recipe of `StepSpec`s: jwst steps wrapped one by one and run
  via `Step.call(..., configure_log=False)`, plus four jstark steps.
- **Recipe controls:** `s1.show()`, `s1.set(step, skip=..., **kwargs)`,
  `s1.add_step(...)`. Enabling `custom_bias` automatically skips `superbias`.
- **Running:** `s1.run(segments=None, start=None, stop=None, model=None,
  save_after=None, save_variances=True)`. `save_variances=False` drops
  `VAR_POISSON`/`VAR_RNOISE` from the rateints (40% smaller; unused by jstark).
  `ExposureCleaner.run(remove_inputs=True)` deletes each rateints file once
  the next segment is cleaned (see reduction.rst, "Disk space").
  - It runs on all segments by default.
  - `stop=` returns the in-memory model.
  - `start=` needs `model=` (in-memory, or a file saved with `save_after`);
    otherwise it raises an error.
- **Outputs:**
  - `*_rateints.fits` per segment;
  - `*_stage1diag.npz` per segment (trace/background masks, signal image, the
    removed 1/f profiles, jump statistics, bias scale factors);
  - `<exposure>_stage1_log.json`.
- **Masks** are built once, from the first segment processed, and reused
  for all segments (or set with `s1.set_trace_mask`).

**Default NIR order:** `group_scale → dq_init → saturation (n_pix_grow_sat=1)
→ consistent_saturation → superbias (or custom_bias) → refpix → group_bkg →
linearity → dark_current → [charge_migration] → temporal_jump → ramp_fit (OLS_C)
→ gain_scale`.

**MIRI order:** `group_scale → dq_init → emicorr → saturation →
consistent_saturation → [firstframe, off] → lastframe → reset → linearity →
[rscd, off] → dark_current → [refpix, off] → [group_bkg, off] → temporal_jump →
ramp_fit → gain_scale`. Since 2026-11-18 this matches the official TSO
pipeline (CRDS `pars-detector1pipeline` for TSOVISIT=True skips rscd and
refpix; jwst 3.0 skips firstframe by default; lastframe runs). See §6.9.

**Defaults per mode:**

| Mode | `group_bkg` | Dark | Other |
| --- | --- | --- | --- |
| NIRSpec (all gratings) | column `median` | off | |
| NIRISS SOSS | column `diff` | on | |
| NIRCam F444W / F322W2 | row `readout`, order 1, `wing_max=200` | off | `refpix` with side reference pixels, odd/even columns |
| MIRI LRS / F1500W | off | on | ramp fit uses all usable groups (see §6.9) |

The jwst `jump` and `clean_flicker_noise` steps are in every recipe but skipped.
`charge_migration` is skipped. `custom_bias` is skipped (optional).

#### Custom step: `consistent_saturation`

- **What it does:** if a pixel saturates at group *g* in ≥ `min_frac` (1%) of
  integrations, groups ≥ *g* are flagged SATURATED in **every** integration.
  - The map is built over **all segments** by a pre-pass
    (`compute_saturation_map`), which runs only the recipe up to `saturation`.
  - It is saved as `<exposure>_saturation_map.fits`.
  - `scope='segment'` avoids the pre-pass; `saturation_map=` takes your own
    map.
  - For tests: `s1.compute_saturation_map(segments=[0])` first.
- **Why:** partially saturated pixels otherwise switch between e.g. 4 and 5
  fitted groups, and their rates jump by 3–8% (§6.6). The switching could also
  follow the transit, since fewer pixels saturate in transit.

#### Custom step: `custom_bias` (off by default)

- **Methods:**
  - `'scaled'`: CRDS superbias × a scale factor from group 0 in background
    pixels (Eureka!-style); `mode` = per_int / mean / smooth.
  - `'self'`: bias = median over integrations of (2·g0 − g1), generalised as
    g0 − frac·(g1 − g0) with frac = ((nframes+1)/2)/(nframes+groupgap).
    Falls back to CRDS where undefined.
  - `'user'`: a 2D array or FITS file.
- **Result:** on G395H, `self` removes the CRDS bias mismatch (§6.5). A static
  offset doesn't change slopes, so this is mainly for correct absolute counts
  (linearity).

#### Custom step: `group_bkg` (group-level background + 1/f)

- **Methods** (`axis='column'` or `'row'`):
  - `'median'`: sigma-clipped median of background pixels per column, or per
    row and amplifier. Amplifiers are equalised first, using all their
    background pixels. Amplifier-rows with fewer than `min_pixels` background
    pixels fall back to the full-row value.
  - `'poly'`: polynomial along each column/row, fitted to background pixels.
  - `'diff'` (exoTEDRF-like): subtract median frames per group scaled by a
    white-light factor, then take stripe medians of the residuals. Removes only
    the time-variable part; the static background stays and is removed at the
    integration level. `use_source_pixels=True` uses all pixels with
    inverse-variance weights (weights from each pixel's temporal residual
    scatter). **Not recommended**: it was worse in every test (§6.2, §6.3).
  - `'readout'` (NIRCam default): on the `diff` residuals, each amplifier's
    row offset = a smooth polynomial in read time (`readout_order`) + a common
    mode shared by all amplifiers read at the same moment. The model fills
    amplifier-rows without background; directly measured rows are kept
    (`readout_direct=True`).
  - `'rowcol'`: amplifiers equalised, then one row offset common to all
    amplifiers (median of the whole row's background pixels), then column
    offsets. Tested for NIRCam (§6.4.1); not better than `readout`.
  - `wing_max` (`diff` / `readout`): the offsets are also measured on faint
    trace pixels (median signal per group < `wing_max` DN). The difference
    images remove the static starlight, and in the wings flux changes are far
    below the 1/f offsets. An amplifier-row without background pixels needs
    ≥ `wing_min_pixels` (100) wing pixels, otherwise the model fills it.
    NIRCam default: 200 DN (§6.4.1). No gain on SOSS (§6.3.1).
  - The official `clean_flicker_noise` step is also available. Its `fft` mode
    is NIRSpec-only and doesn't fit NIRCam's 4 amplifiers.
- **Common rules:** saturated or do-not-use groups are excluded from the
  statistics but still corrected. Masks come from `build_trace_mask`.

#### How the background region is chosen (trace mask)

1. **Quick source image:** median over up to 200 integrations of (last usable
   group − first usable group), scaled to the full ramp. Computed after
   `superbias` / `refpix`, so it is bias-free and has very high S/N.
2. **Exclude unusable pixels:** `DO_NOT_USE`, `REFERENCE_PIXEL`,
   `NON_SCIENCE` and `DEAD` pixels can never be background.
3. **Threshold each spectral pixel** (each column; each row for MIRI LRS):
   - The background level is a sigma-clipped median: median → reject values
     more than 2.5 × MAD-sigma away → repeat (≤ 5 passes).
   - The noise is estimated from pixels *below* the background (starlight
     only adds flux).
   - Source = pixels above background + `nsigma` (3) × noise.
   - Worked example (G395H NRS1, column x = 1500): pass 1 median 10.5 DN
     (pulled up by the trace) → pass 2 0.9 DN → pass 3 −0.2 DN, converged on
     15 background pixels. Noise 0.3 DN, threshold 0.9 DN against a 10,345 DN
     peak, so the mask reaches far into the PSF wings.
4. **Clean and grow:** remove isolated detections (2×2 opening, or components
   < 10 px) **before** smoothing; a maximum filter of 5 along the dispersion;
   then dilate by `pad`.
5. **Guarantee a minimum:** background = everything else that is valid, with
   at least `min_pixels` per column/row (the lowest-signal pixels are added if
   needed).

- **Defaults:** `nsigma=3`; `pad` 2 (NIRSpec), 3 (SOSS, NIRCam, LRS), 5
  (imaging); `min_pixels` 4 (NIRSpec), 10 (others).
- **Alternatives:** `method='centroid'` (fixed band of ±`halfwidth` around a
  polynomial trace), `'both'`, or `s1.set_trace_mask(...)`.
- **Assumption:** empty pixels must dominate a column. If the trace fills
  most of a column, use `centroid` or your own mask.
- **Typical background fractions:** G395H NRS1 ~50%, NRS2 ~39%, PRISM ~38%,
  SOSS ~48%, F444W ~57%, G395M ~53%.

#### Custom step: `temporal_jump` (cosmic rays at group level)

- **Detection:** compute each pixel's group differences; compare each with a
  **leave-one-out** running median over 11 integrations (the tested
  integration excluded). The noise is the MAD of the residuals over time, with
  a √2 × readnoise floor (CRDS). Threshold 10σ, two-sided. Optionally flag the
  4 neighbours.
- **What happens to a hit:**
  - `mode='replace'` (default for < 10 groups): the bad difference is
    replaced by its running median and the ramp rebuilt. No groups are lost,
    but ERR doesn't know about the substitution.
  - `mode='flag'` (≥ 10 groups): JUMP_DET is set on the group after the jump,
    and jwst OLS splits the ramp there. One difference is lost; all groups are
    kept.
- **Example:** a cosmic ray during the 4th of 10 groups corrupts only the
  group-3 → group-4 difference (all later groups carry the same offset).
- **Larger events:** for snowballs and showers, use `flag_neighbors=True` or
  the jwst `jump` step (`expand_large_events`).

#### `ramp_fit`

- jwst OLS_C (`LIKELY` is available).
- `firstgroup` / `lastgroup` accept an integer or `'auto'`
  (`find_linear_group_range`: the source-summed group-to-group increases
  within `tol` of their mid-ramp plateau; computed once, reused for the
  exposure).
- **Guard:** if a selection would leave < 3 usable groups, it is dropped with a
  warning. jwst would otherwise silently use all groups (when
  firstgroup ≥ lastgroup) or leave pixels without a rate.
- **Linearity** uses the unmodified jwst step and the CRDS reference. A
  different reference can be passed with
  `s1.set('linearity', override_linearity='file.fits')`.

### 5.2 Stage 2 (wavelength solution)

- `Stage2(rateints dir).run()` evaluates the WCS on the **full subarray grid**
  (the data geometry is kept) and writes `<exposure>_wavelength.fits`. That
  file also holds SOSS trace positions and the NIRSpec in-slit mask.
- **Per mode:**
  - NIRSpec: slit WCS (`nrs_wcs_set_input`, S1600A1), evaluated with
    `with_bounding_box=False`.
  - NIRCam: `assign_wcs` + `extract_2d` (handles source offsets), mapped back
    onto the subarray.
  - SOSS: PASTASOSS `get_soss_wavemaps(PWCPOS)` for orders 1–3, plus traces.
  - MIRI LRS: slitless WCS.
  - MIRI imaging: none.
- Uses a lightweight 2D model (first integration only).
- Optional `flat_field`, `photom`, ... per segment → `*_calints.fits`. They are
  not needed for relative work. For NIRSpec they require `extract_2d`, which
  crops.

### 5.3 Cleaning (`ExposureCleaner` / `CubeCleaner`)

- **Pass 1** (`compute_global`) reads segments one at a time and builds:
  - the median frame and the robust scatter image (medians of per-segment
    values);
  - the DQ-based always-bad map (bad in > 50% of integrations; flags
    `BAD_DQ_FLAGS`; **SATURATED is deliberately excluded**, §6.6);
  - hot / cold / noisy pixels;
  - trace and background masks;
  - the **exposure-wide cosmic-ray noise map** (`residual_sigma`,
    leave-one-out).
- **Pass 2** (`clean_segment`): each segment is padded with `window // 2 + 1`
  (6) integrations from its neighbours, then runs `fix_errors →
  find_cosmic_rays (5σ, exposure-wide sigma) → replace_bad_pixels →
  [subtract_background]`. The padding is trimmed and the segment saved as
  `*_cleaned.fits` (SCI, ERR, BADPIX 2D, CRMASK 3D, INT_TIMES, TRACEMASK,
  HISTORY).
- **`save_info`** writes `<exposure>_cleaninfo.fits`: BADPIX, MEDIAN, STD,
  CRSIGMA, TRACEMASK, BKGMASK, WAVELENGTH, all INT_TIMES, the SEGMENTS table
  and HISTORY. `ExposureCleaner.load(info)`, `load_segment(i)` and
  `iter_segments()` serve extraction.
- **`CubeCleaner` methods:**
  - `fix_errors`: flags NaN data and bad errors; errors are replaced by the
    pixel's median error.
  - `find_hot_pixels`: median frame vs the **neighbour median excluding the
    pixel**, along the dispersion (8 neighbours for imaging). Flag if
    > `nsigma`(10)·σ_line + `rel_tol`(0.25)·|neighbours|. Noisy pixels:
    scatter > 3× the neighbours'.
  - `find_cosmic_rays`: leave-one-out running median in time, or the
    scaled-median method.
  - `replace_bad_pixels`: transient pixels → the pixel's running median in
    time; persistent pixels → linear interpolation along the dispersion
    (≤ 5 px), then a widening box median.
  - `subtract_background`: per column (per row for LRS) median or
    polynomial.
  - `subtract_background_model`: scaled 2D model (e.g. SOSS zodiacal light).
  - `to_apphoto`: imaging data into `ApPhoto` (now `jstark.extraction.ApPhoto`).
  - `white_light`.
- **Conventions:**
  - `badpix`: 1 = good (as `ApPhoto`).
  - `crmask`: True = bad.
  - `good_mask`: the 3D combination of the two.
  - `times` = BJD_TDB − 2400000.5 (jwst convention); `bjd` = full BJD_TDB.
- `CubeCleaner.from_files(..., segments=[0])` stitches into memory and is only
  for single segments or small data.

## 6. Results (all on segment 1 of each dataset)

### 6.1 Overview

The **white-light ratio** is the point-to-point scatter of the summed brightest
trace pixels, divided by the scatter if those pixels' noise were independent.
1 means no correlated noise. In every mode, each pixel's own scatter matches its
ERR (0.94–1.06), so the error propagation is sound.

| Mode | Segment 1 shape | Stage 1 (s) | Jumps / int | CRs / int | White-light ratio |
| --- | --- | --- | --- | --- | --- |
| PRISM | 6100×5×32×512 | 116 | ~0.6 px | 2.7 | 1.19 |
| G395H NRS1 | 1525×6×32×2048 | 113 | 0.014% | 14.7 (8.3 after LOO fix) | 1.08 |
| G395H NRS2 | 1525×6×32×2048 | 91 | 0.014% | 23.5 | 1.18 |
| G395M NRS1 | 1023×4×32×2048 | 55 | 0.008% | 6.3 | 1.19 |
| SOSS | 190×4×256×2048 | 160 | 0.054% | 146 | 2.31–2.43 |
| F444W | 759×7×64×2048 | 344 | 0.011% | 58.6 | 4.82 → 4.03 (readout) |
| F322W2 | 738×4×64×2048 | 183 | 0.005% | 11.0 | 6.05 → 5.29 (readout) |
| MIRI LRS | 312×64×416×72 | 75 | 0.077% | 14.3 | 1.46 |
| MIRI F1500W | 678×47×128×136 | 192 | 0.017% | 1.5 | aperture photometry: 1.16–1.34 (group 12 start), 740 ppm at group 0 |

- Jump rates scale with integration time (about 0.0026%/s), as expected for
  cosmic rays.
- Cleaning takes about 20–25 s per segment.
- NIRCam's slowness is jwst `refpix` (213 s for F444W).

NRS2 3.82–5.17; G395M 2.73–5.18 (trace x ≈ 685–2043); SOSS orders
0.85–2.83 / 0.50–1.41 / 0.50–0.96; F444W 3.84–5.05; F322W2 2.40–4.05; LRS
5–12 µm on rows 142–388.

#### 6.3.1 How much of the SOSS excess is leftover 1/f? (2026-11-14)

**Question.** Is the SOSS excess after extraction (extraction_notes.md §5.6:
per column 1.20 order 1 / 1.44 order 2; white light 2.08 / 1.98) leftover
1/f that a better group-level method would remove?

**The coherent part is removed.**

- **Keep `diff` without wing pixels for SOSS.** The per-column metric
  confirms it over `median`, and the order-2 white light agrees.
- **Rank 1/f methods** by the per-column and binned ratios after dividing by
  the white light, not by the white light.
- **Stage 1 1/f is closed for SOSS.** The remaining excess belongs to
  extraction and light-curve fitting: PSF-shape regressors, common-mode
  correction, a static instead of per-integration background.
- **Method caveat:** before `temporal_jump`, cosmic rays (spread over
  neighbouring pixels) inflate covariance-based estimates; mask outliers and
  their halo first. A first estimate without masking ("half of the
  per-column excess") was inflated this way.

### 6.4 NIRCam correlated noise

**Cause.** GRISMR disperses along the fast-read direction, so each 1/f stripe
hits many wavelengths at once. In trace rows, 2–3 of the 4 amplifiers have no
background pixels (Schlawin et al. 2020, arXiv:2010.03564; STScI known issues).

**What the measurements show:**
- **96% common mode:** of the row-to-row 1/f, 96% is shared by all four
  amplifiers (correlation 0.92–0.97; 36 DN rms per amplifier-row).
- **Small, fast amplifier-specific part:** about 6 DN rms, decorrelating
  within about 5 rows (25 ms). The trace spans about 28 rows (150 ms), so it
  cannot be interpolated.
- **The excess is additive:** it grows with aperture size (F322W2: brightest
  20% of pixels 3.3×, 50% 6.0×, full mask 9.3×). Jitter would do the opposite;
  centroid jitter is only 0.005 px.
- **Background helps:** the F322W2 amplifier that has background in the trace
  rows reaches 1.76×; the others are at about 4×.
- **4-integration bias pattern:** every 4th integration is about 55 DN lower
  in the raw data (fast frame resets, Schlawin et al. 2023, arXiv:2211.16727).
  It leaves a ±200–290 ppm pattern, but explains only a little of the excess
  (F444W 4.8 → 4.0, F322W2 6.0 → 5.6 when removed).
- **No red noise on one segment.** The excess is high-frequency and correlated
  across pixels.
- **Amplifier separation is essential:** a row median *without* amplifier
  separation gave 14.15× on F322W2.

**Methods compared** (white-light ratio, F322W2 / F444W):

| Method | F322W2 | F444W |
| --- | --- | --- |
| readout, order 0, common only | 5.19 | 4.09 |
| **readout, order 1 (default)** | 5.29 | **4.03** |
| readout, order 0, + direct | 5.30 | 4.14 |
| row median per amplifier (old default) | 6.05 | 4.82 |
| readout, order 2 | 8.19 | 5.10 |
| no group-level step | 8.21 | — |
| readout, order 3 | 8.27 | 5.52 |
| diff, all pixels weighted | 8.80 | 8.57 |
| row median, amplifiers not split | 14.15 | — |

**What failed and why:**
- **Offsets from trace pixels** (weighted diff; a scene model with flux and
  x/y-jitter terms, about 130×): along a grism row the spectrum varies slowly,
  so a flux change in a row is degenerate with a row offset.
- **Side reference pixels after `refpix`:** |r| = 0.13–0.34 with the
  amplifier-specific offsets.
- **jwst fft mode:** NIRSpec-only.
- **Caveat:** a quicker CDS-only test (300 integrations) didn't show the
  readout gain, so confirm it on a full exposure.

**For extraction:** optimal and covariance-weighted extraction, and a phase-of-4
regressor for the bias pattern.

### 6.6 Saturation (WASP-39 PRISM)

- **Scale:** 106 trace-core pixels (rows 14–15, about 1–2 µm) saturate in
  about every integration, keeping 1–4 of 5 groups.
- **Neighbour growth stays on.** jwst's `n_pix_grow_sat=1` is needed: without
  it, neighbours of the core are 2.5–3× too bright (85,577 vs 28,398 DN/s) and
  scatter up to 2.8× their ERR, because of charge spilling.
- **Switching group counts:** 66 pixels change their number of usable groups
  between integrations. That changes their rate by 3–8% (normal scatter
  0.4–1.6%). With `consistent_saturation`, the worst 10-column bins went from
  2.45× / 3.69× their ERR to 1.19× / 1.16×.
- **DQ semantics:** jwst sets `SATURATED` in rateints DQ for any partially
  saturated pixel, even with a valid slope. With SATURATED counted as bad, 270
  pixels at the spectral peak would have been replaced; now only the 18 with
  no rate are (those with only group 0 left; `suppress_one_group=True`).
- **Full exposure (2026-11-14, extraction_notes.md §5.14):** the
  exposure-wide map has the same 270 pixels as segment 1. Against the
  published light curves the saturated columns are less noisy (−30% where
  the core saturates at group 3) but their transit depths are biased deep:
  about +500 ppm (group 3), +1500 ppm (group 2) and +7000 ppm (columns
  whose core keeps only group 0). The steps follow the first saturated
  group exactly. Per-pixel ramps of different length in one column plus the
  flux-dependent PSF (brighter-fatter) cause it. The published reductions
  flag whole columns at the first saturated group. An option to do the same
  in `consistent_saturation` is one of the fixes to test.

### 6.9 MIRI ramp start (RSCD)

- **The distortion:** early group-to-group increases are 50–120% too high in
  group 1 and linear to about 1% from group 12, for both LRS and F1500W.
  `rscd` flags 8 groups on LRS but only groups 0–1 on F1500W SUB128.
- **The MIRI dark** adds a fixed 1–3% group-to-group pattern to summed
  increases, the same in every integration. It is harmless, but it makes
  `firstgroup='auto'` unreliable at tight tolerances.
- **History of the decision:** I first set the MIRI default to `firstgroup=12`
  on linearity grounds, then **reverted it** after testing (GJ 3929 F1500W,
  4-px aperture, sky 15–25 px, integrations 60+):

  | Start group | Scatter (ppm) | Median error (ppm) | First 10 ints vs late | Red-noise factor |
  | --- | --- | --- | --- | --- |
  | 0 (default) | 740 | 627 | −0.95% | 4.07 |
  | 4 | 802 | 643 | −0.97% | 4.02 |
  | 8 | 847 | 677 | −0.97% | 3.89 |
  | 12 | 944 | 717 | −0.97% | 3.77 |

- **Conclusion:** the distortion is constant in time (it only rescales the flux,
  by about 0.3%), the early-visit ramp is detector settling, and trimming only
  costs precision. **Default: fit all usable groups.**
- **Still to do:** compare event depths for start groups 0 vs 4–8 on a full
  exposure.
- **2026-11-18, superseded for LRS:** the "fit all usable groups" decision

  pipeline, which skips `rscd`, this deepened the WASP-43 b transit by
  55 ± 11 ppm (fitting_notes.md §5.7 item 10). **User decision:** MIRI now
  follows the official TSO configuration: `firstframe`, `rscd` and `refpix`
  skipped, `lastframe` kept.

ERS 1366 obs 3, NRS1 and NRS2, NRSRAPID **70 groups** x 465 integrations
(63 s), 3 segments. The first NIRSpec data with many groups (TOI-561: 6).
All defaults except `ramp_fit maximum_cores='4'` (memory). Per detector:
Stage 1 506-530 s (segment 204 s: `temporal_jump` 84 s, `group_bkg` 33 s,
`ramp_fit` 22 s, `refpix` 19 s; saturation pre-pass 22 s), cleaning 13 s;
peak RSS 9.8 (NRS1) / 13.5 GB (NRS2), at least 51% memory free.

- `temporal_jump` runs in `mode='flag'` (>= 10 groups): 35,400-36,000 jumps
  per segment, 0.32-0.34% of pixels per integration. Cleaning: 144-161
  transient flags per integration, spread in time (84-389), mostly on
  faint pixels (median signal ~0; fewer on the trace rows, where small hits
  hide in the photon noise), 2% from pixels flagged >= 10 times. Both are
  the expected cosmic-ray rate for 63 s: ~5 events/cm2/s x 0.21 cm2 x 63 s
  ~ 67 events x 2-3 px. The per-second rate of §6.1 (0.0026%/s, from short
  integrations) underestimates it.
- **Saturation map and static bad pixels (fixed).** The star does not
  saturate. The map held 18 (NRS1) / 225 (NRS2) pixels: 3x3 blocks around
  static bad pixels of the CRDS mask (`DO_NOT_USE` + `DEAD` / `HOT` /
  `LOW_QE`), which the jwst `saturation` step flags (mostly from group 0)
  and grows onto their neighbours (`n_pix_grow_sat=1`; official pipeline
  the same). Extraction's `min_groups=2` then set 13 NRS2 columns
  (3-column groups) to NaN for the whole exposure. Now
  `compute_saturation_map` leaves out static `DO_NOT_USE` pixels (pixel DQ
  after `dq_init`) and neighbours within the growth radius that first
  saturate at the same group, and saves them in a `STATIC` extension
  (header `NSTATIC`); `consistent_saturation` still uses them, so the
  Stage 1 processing is unchanged (`Stage1._static_saturation`, test
  `test_static_bad_pixels_left_out_of_saturation_map`). After the fix:
  NRS1 0 pixels, NRS2 9 (pixel (14, 60) saturated at group 0 but not in
  the CRDS mask, plus its growth; outside the aperture). No NaN columns.
- The mirror tilt at integration 269 and the extraction changes it needed:
  extraction_notes.md §5.17. Stage 1 and cleaning are not affected by it.

## 9. Quick usage

```python
from jstark.reduction import Stage1, Stage2, ExposureCleaner, CubeCleaner

if __name__ == '__main__':
    s1 = Stage1('/data/NRS1', outdir='/data/NRS1/reduction')   # exposure='nrs1' to choose
    s1.show()
    s1.set('group_bkg', method='poly', poly_order=1)            # any step, any parameter
    s1.run()                                                    # all segments

    m = s1.run(segments=[0], stop='refpix')                     # inspect mid-way ...
    s1.run(segments=[0], start='group_bkg', model=m)            # ... and resume

    wfile = Stage2('/data/NRS1/reduction').run()['wavelength']
    ec = ExposureCleaner('/data/NRS1/reduction', wavelength=wfile)
    info = ec.run(background=True)
    for i, seg in ExposureCleaner.load(info).iter_segments():
        ...   # seg.data, seg.err, seg.badpix, seg.crmask, seg.times, seg.wavelength

    # imaging (MIRI F1500W): seg.to_apphoto(aprad=4, sky_rad1=15, sky_rad2=25)
```

For tests on one segment:

```python
s1.compute_saturation_map(segments=[0])
s1.run(segments=[0])
```

Diagnostic plots: `jstark.reduction.diagnostics` (`plot_masks`,
`plot_group_bkg`, `plot_jumps`, `plot_rateints`, `plot_cleaning`,
`plot_wavelength`, `load_stage1_diagnostics`).
